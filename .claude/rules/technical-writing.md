- Introduce concepts before using them. If a parameter (fee tier, slippage, etc.) appears in an example, the explanation should come before or alongside the example, not in a later section.
- Describe "why" then "what" then "how."
- Most pages should start with a summary paragraph that gives a high-level overview of the topic and its motivation. This should be followed by a more detailed explanation of the concept, and then finally the technical details and code examples. This structure helps readers build intuition before getting into the specifics.
- Use clear, concise language. Use simple terms rather than jargon and technical terms where possible, and explain any necessary terms when they are first introduced.
- After writing, read through the content to ensure it flows logically and is easy to understand. Consider whether someone new to the topic would be able to follow along and grasp the key points. Rewrite aplenty to improve clarity and flow. Strip words that don't add meaning. Use shorter sentences and paragraphs to enhance readability.
